## 1. 产品定位

**一句话**：WorkGremlin 是一个本地桌面应用，把「多 agent 协作团队」的运行过程变成一块**看得见的工位**和一份**查得到的对话记录**。

当前用 CodeBuddy / 类 Claude-Code 的 multi-agent 团队跑任务时，用户面对的是一堆终端日志和一堆散落的 JSON 文件：谁在干活、谁卡住了、谁等谁的消息、刚才那句指令到底发出去没有，全都不可见。WorkGremlin 解决的就是这个**可观测性缺口**。

定位边界：

| 是 | 不是 |
| --- | --- |
| 本地单机的**只读监控 + 轻量管理**终端 | 云端 SaaS / 多人协作平台 |
| 团队运行过程的**仪表盘** | agent 的调度器 / 编排引擎（不替 runner 派活） |
| 对现有团队目录的**观测 + 上报接入** | 替换 CodeBuddy 团队机制本身 |
| 面向「正在带一支 agent 团队干活的人」 | 面向 agent 本身 |

## 2. 目标用户

| 画像 | 特征 | 核心诉求 | 关键场景 |
| --- | --- | --- | --- |
| **P1 主力：AI 团队操盘手**（开发者 / Tech Lead，正在用 multi-agent 跑一个真实项目） | 同时挂 3~8 个 agent；自己也在写代码；讨厌切窗口看日志 | 「一眼看清谁在干嘛、谁卡住了，卡在哪」 | 并行开发时盯盘；发现某 agent 阻塞 10 分钟立刻介入 |
| **P2：Agent 工程调优者**（做 prompt / 工作流调优） | 反复跑同一批任务对比效果；关心耗时分布和消息往返 | 「复盘一次完整协作：谁等了多久、消息往返多少次、产出在哪」 | 跑完一轮后回看时间线，定位协作瓶颈 |
| **P3：团队负责人 / 旁观者** | 不亲自下场，想知道钱和时间花在哪 | 「不看日志也能汇报进展」 | 开会时投屏工位视图；导出会话纪要 |

> 本阶段以 P1 为唯一设计靶心，P2/P3 的需求只在「不增加 P1 复杂度」的前提下顺带满足。

## 3. 核心功能清单

优先级约定：**P0 = 没有它产品不成立**（M0~M2 必须交付）；**P1 = 显著好用**（M3）；**P2 = 锦上添花 / 可延后**。

### 3.1 P0（必须）

#### P0-1 工位视图（Workstation View）
一块「办公室」区域，一个成员一张工位卡片，**自动实时刷新**（轮询 / 推送均可，但**不允许手动点按钮才更新**）。每张卡片至少展示：

| 字段 | 说明 | 数据来源 |
| --- | --- | --- |
| 成员名 / 角色 | leader / researcher / coder / tester … | roster（`config.json`）+ 上报 |
| **状态徽标** | 三态 `busy` / `idle` / `blocked`（2026-10-21 起；v0.1 的「5 主状态 + degraded」已删除，见 §4） | 运行中任务 → busy；会话授权等待 → blocked；否则 idle |
| **当前任务** | 任务标题 + 一句话描述 | 上报 |
| **进度百分比** | ~~0~100% 进度条 + 三层降级~~ **已移除**：`tasks.progress` 仅作可选上报值，未上报显示「进度未知」 | 上报（可选） |
| **正在读写的文件** | 当前活跃文件路径（最多显示 3 条），**区分 `read` / `write`**：读=弱化灰图标，写=高亮色条（`edit` 已取消） | 上报（`file_activity.op`） |
| **最近产出** | 最近生成的产物（文件 / 提交 / 结论） | 上报 |
| **已耗时** | 当前任务已用时（秒级走动） | 由 `task.start` 时间戳推导，前端时钟走动 |
| 数据源标记 | 「上报值」/「推断值」图例（无 `degraded`） | 系统内部 |

**进度百分比三层降级（v0.1 历史提案，已废弃）**：当前没有进度条，也没有推导 / 条纹动画；只显示 agent 显式上报的值，没有就是未知。

**容量与布局（Q3 已定）**：
- 成员上限 **16 人**（≥16 不串台是 P0 验收项）。
- **≥5 人**自动切**紧凑模式**：卡片缩小为「头像 + 状态点 + 单行任务」。
- **>16 人**时按 team 分页 / 折叠。
- 上述阈值可在设置里覆盖。

非功能要求：
- 状态变更后 **P95 ≤ 300ms** 反映到 UI（端到端，含传输）。
- 支持 **≥16 个成员**同屏不串台、不错位。
- 状态未知时**必须显示为未知/灰显，严禁编造或猜测数值**。

#### P0-2 对话记录窗口（Conversation View）
展示团队内**全部**消息流（不是只展示某一个成员的收件箱）。

- 每条消息展示：时间、发送方 → 接收方、消息类型、内容（长内容可展开看原文 JSON）。
- **过滤**：按成员（多选）、按时间范围、**按消息类型**。
- **搜索**：关键字全文搜索（M2 起用 SQLite FTS5，采用 **`tokenize='trigram'`** 分词器，零依赖且支持中文子串匹配；`unicode61` 会把整段中文当成一个 token，**不可用**）。**1~2 字的短查询自动降级为 `LIKE` 扫描**（限定时间范围控开销），因为 trigram 对 <3 字召回差。
- **滚动行为**：默认滚动到底自动跟随新消息；用户手动上滚时暂停跟随并显示「N 条新消息」提示，回到底部恢复跟随。
- **完整性**：消息**不丢、不重**（以 `dedupe_key` 保证幂等）、按时间有序。
- 容量：单 team **10 万条**消息下滚动流畅（虚拟滚动）。

#### P0-3 数据接入与落盘
- **B 路线（主，真值来源）**：agent 通过 `packages/reporter`（SDK / CLI）主动上报 → HTTP ingest → SQLite。
- **A 路线（兜底）**：`chokidar` 监听 `{workspace}/.codebuddy/teams/{team}/`，解析 `config.json`（roster）与各成员 mailbox（仅能拿到收件）。
- **降级规则（已废弃）**：v0.1 曾计划「无心跳 60s → `degraded`」，该机制已删除。现在没有心跳，也没有超时能改变状态。
- 存储：SQLite（better-sqlite3）+ 内存快照；消息保留 **90 天 / 单 team 10 万条**，超限先导出 JSONL 归档再删除（归档逻辑 M1，M0 只预留 `archived_at` 与索引）。

#### P0-4 范围与多团队
- **单 workspace、多 team**：只观察当前工作区，但 `team` 是数据模型一等字段，UI 支持 team 切换。
- 多 workspace **不做**（架构预留，M0~M3 不实现）。

#### P0-5 连接与自解释
- 顶部连接状态条：WS 连接状态、数据源（上报 / 推断）、最近同步时间。
- 断线自动重连（指数退避），失焦/休眠恢复后自动补齐。

#### P0-6 演示模式（当前为界面按钮，不再有 `--demo` / `MOCK=1`）
M0 就要有：内置确定性假数据源，既能给用户演示，也是 E2E 的确定性数据源。入口是办公室 HUD 的「演示模式」按钮 → `POST /api/v1/workspace`（空路径）打开隔离的演示工程。

#### P0-7 消息脱敏与凭据防护（安全底线）
- agent 对话常粘贴 `.env` / 密钥，**写入 SQLite 前必须正则脱敏替换为 `***`**，原文**不入库**（不是仅 UI 隐藏）。
- 规则至少覆盖：`sk-[A-Za-z0-9]{16,}`、`AKIA[0-9A-Z]{16}`、`ghp_[A-Za-z0-9]{36}`、JWT（`eyJ...`）、`-----BEGIN *PRIVATE KEY-----`、`(?i)(password|passwd|pwd|token|secret|api[_-]?key|authorization)\s*[:=]\s*\S+`、URL 内嵌凭据 `://user:pass@`。
- UI 对命中规则的消息显示「本条已脱敏」标记。
- M0 只预留 `redaction` 钩子（一个可替换的 `redact(content)` 中间件点），M1 随消息入库一并启用。
- **真正的底线是「脱敏在入库前完成」** —— 即 DB 里**从一开始就不存在明文**。若在 DB 中发现明文，那是 **P0 级缺陷**，不是靠任何开关能补救的。脱敏必须发生在**入库与 FTS 建索引之前**。
- **纵深防御（不要当作安全底座）**：`secure_delete` 只是额外一层，防的是「删除已脱敏消息时旧页残留」。
  - **`secure_delete` 是连接级 PRAGMA，不是表级**，故采用**双连接**：**写入连接** `secure_delete=OFF`（高吞吐，承担 1000 事件/s 稳态）；**删除/归档连接** `secure_delete=ON`（仅用于归档删除与手动删除）。正常流程几乎不删，稳态吞吐不受影响。
  - WAL：显式设置 `wal_autocheckpoint`；归档/删除后在删除连接执行 `PRAGMA wal_checkpoint(TRUNCATE)`；`.db` / `.db-wal` / `.db-shm` 文件权限 `0600`。
  - **禁止为吞吐自行关闭 `secure_delete`**；若实测仍冲突，走「归档批量化 + 降频（同步改异步批处理）」，不削弱安全项。

**看原文的加密通道（Q9 已定，归 M3 / P1，M0/M1 不实现）**
- **默认关闭**（不存原文）。开启需用户在设置里**显式确认并理解风险**。
- 开启时：优先用 **OS 钥匙串**保管随机数据密钥（macOS Keychain / Windows DPAPI / Linux libsecret，统一用 `keytar` 封装）；**口令派生（scrypt / argon2）作为无钥匙串环境的降级方案**。
- 约束：原文与正文**分表存储**、独立加密；**每次会话重新授权，不记住解锁状态**；查看原文**记入事件日志**。

## 4. 状态语义（已被 2026-10-21 重构取代）

> **本节 v0.1 的「5 个主状态 + 1 个正交标志」已全部删除，仅作为历史记录。** 当前模型恰好三态，权威定义见 `docs/requirements.md` §5。

| 状态 | 含义（当前实现） | 判定来源 |
| --- | --- | --- |
| `busy` | 正在执行任务 | 该成员 / 会话存在 `tasks.state='running'` 的任务；常驻 gremlin 可借用同名 ghost 的 busy（仅展示） |
| `blocked` | 仅在等待授权 | 该会话存在 `session_status.state='blocked'` 行（hook 的 `PermissionRequest` / 授权类通知） |
| `idle` | 其余情况 | 既无运行中任务，也无 blocked 行 |

优先级固定为 **`blocked` > `busy` > `idle`**；同优先级取最早的 `stateSince`。状态只由持久化数据推导，**没有心跳、超时、TTL、`offline` / `online` / `error` / `unknown`，也没有 `degraded` 标志**。

## 7. 已拍板决策（本版已并入，不再讨论）

1. 数据源：**A + B 混合**，B（主动上报）为真值；A（目录监听）未实现。**无心跳、无 60s 超时、无 `degraded`**（2026-10-21 删除）。
2. 桌面外壳：**Electron 38 + Vue 3 + Vite + TypeScript**。
3. 数据库：**better-sqlite3 + @electron/rebuild**（不用 `node:sqlite`）；Electron 版本锁定并接 `postinstall`。
4. 范围：**单 workspace、多 team**；多 workspace 不做。
5. M0：**一次性交付全骨架**（约 30 个文件）。
6. 状态模型：**`busy` / `idle` / `blocked` 三态**（2026-10-21 重构；5 主状态 + degraded 已删除）。
7. 消息保留：**90 天 / 单 team 10 万条**，超限先导出 JSONL 归档再删除（归档逻辑 M1，M0 预留字段与索引）。
8. 平台：**仅 x64**（Linux/Windows/macOS-x64），不出 ARM，打包脚本参数化。
9. 网络盘 / WSL：M0~M2 不支持；读取失败退化为空数据，无 `degraded` 标志；WSL 与时序跳变登记 M3 评估。
10. 演示模式：入口已改为界面按钮（办公室 HUD「演示模式」→ `POST /api/v1/workspace`），**不再有 `--demo` / `MOCK=1`**；确定性假数据源与 mock 渲染三合一。
11. tester 的 15 条可测性契约中 **5 条**（时间源可注入、`createTestApp` 工厂、core 与 Electron 解耦、`data-testid`、确定性 ID）由 coder 在 M0 落地。
12. **存储层安全基线**：**底线是脱敏在入库前完成**（DB 中从不存在明文，出现明文即 P0 缺陷）；`secure_delete` 仅为纵深防御，因其是**连接级** PRAGMA 而采用**双连接**（写入连接 OFF 保吞吐 / 删除归档连接 ON 防残留）+ WAL checkpoint(TRUNCATE) + 文件权限 0600。**两个指标都不放宽**。
13. **FTS5 分词器固定为 `trigram`**，M0 建表即用；短查询（1~2 字）降级 `LIKE`。
14. **通知聚合规则（未实现）**：v0.1 的「S1 触发 / 离线期间合并」规则依赖已删除的 `error` / `offline`，需重新设计；当前唯一候选触发条件是 `blocked` 超过 10 分钟。
15. **macOS 公证豁免**：ad-hoc 签名 + 四处明示未公证说明；不阻塞任何里程碑。
