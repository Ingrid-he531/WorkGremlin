# v0.1.0-beta.1 — 第一版 Beta

2026-10-01 · 标签 `v0.1.0-beta.1`

把本机在跑的各种 AI 编码 agent 变成一间**看得见的办公室** —— 每个 CLI / IDE 插件是一条"楼层"，谁在线、在忙什么、哪一层在干活，一眼扫完。

## 这一版有什么

**三个页面**

- **办公室（主控制台）** —— 屋里的成员、实时相位、当前任务。没装的产品那层灰显；心跳断了标成 degraded（推断值，灰显 + 标注），不假装还活着。
- **任务记录** —— 逐条任务 + 「每日看板」（楼层 × 时间的甘特）+ 汇总报表四个页签（数据总览 / 按工程 / 按模型 / 按楼层）。顶部一层筛选（工程 / 楼层 / 状态 / 时间 / 关键词），三个视图共享；时间档位有全部时间 / 今天 / 昨天 / 过去 7 天 / 过去 30 天 / 这个月 / 上个月 / 自定义。
- **汇总** —— 按工程 / 楼层汇总的报表，可导出 CSV。

**九个楼层，两种取数路子**

| 楼层 | 产品 |
| --- | --- |
| 1F | CodeBuddy（CLI 与 IDE 插件合并） |
| 2F | WorkBuddy |
| 3F | Codex |
| 4F | Claude Code |
| 5F | TraeCode |
| 6F | Qoder |
| 7F | Kilo Code |
| 8F | OpenCode |
| 9F | GitHub Copilot |

有 hook 的产品走上报（实时相位），没有的（7F/8F/9F）直接轮询它自己的落盘库，读成同样的任务台账。

**词元（token）统计**

1F CodeBuddy CLI、3F Codex、4F Claude、7F Kilo、8F OpenCode 五路直接读各楼层自己的会话落盘，按统一口径折算（Anthropic 的 `input` 不含缓存、OpenAI 的 `prompt` 含缓存；Codex 的累计值取每轮差值；Claude 同一次请求的重复记录按 `message.id` 去重），包括缓存读 / 缓存写 / 输出（含思考）。**读不到的一律留空**——"没读到"和"消耗为零"不是一回事，宁可显示「—」也不写 0。

**一条贯穿始终的规矩：只画真值。** 状态、任务、文件、耗时、词元都来自 agent 自己上报或它本地的落盘；拿不到就写「未上报 / —」。没有假进度条。

**中 / 英切换。**

## 怎么跑

前置 Node ≥ 24（Linux 另需 python3 + make + g++，用来编译 better-sqlite3）：

```bash
npm install
npm run launch
```

启动时会把"状态上报 hook"自动写进已装产品的配置（只加/更新自己的条目，改动前备份成 `.bak-workgremlin`）。不想被自动改配置：`WORKGREMLIN_NO_AUTO_HOOKS=1`。

数据都在 `~/.workgremlin/`。起完之后可以在办公室右下角点「演示模式」看一轮完整演示，不需要真的装 agent。细节见 [README](../../README.md#快速开始)。

## 已知问题

- **1F CodeBuddy 的插件形态、2F WorkBuddy、5F TraeCode、6F Qoder、9F Copilot 目前统计不到词元**——不是没接，是这些产品本机落盘里没有可读的用量数据（2F 只有二进制和 settings.json；9F 本机没有会话数据，未验证）。按上面的规矩，这几层如实留空，不写 0。
- **仓库自检里有一条红的**：`npm run test:floors` 的 `[A5] 插件落盘这一路自己仍然列得出会话`。不是这版引入的——那条用例调 `listSessions` 时没传 `pluginRe`，于是落到函数默认的正则上，在自检沙箱里命中的是 9F Copilot 的 session-store.db，返回了别层的会话。线上每个来源各自传自己的 `pluginRe`，所以是**自检的口径过时**，不是产品行为有问题；但这条断言现在等于没在验它想验的东西，待修。其余 39 个 `test:*` 全绿。
